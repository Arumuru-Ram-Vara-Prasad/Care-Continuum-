Problem Formulation & Scope

10 pts
Research Question: "Can we predict whether a diabetic patient will be readmitted to the hospital within 30 days of discharge, using clinical encounter data available at the time of discharge?"
Unit of Analysis
Hospital Encounter
Each row = one encounter; patients may have multiple encounters
Target Variable
readmitted_30d
Binary — 1 if original label was "<30", 0 otherwise
Prediction Time
At Discharge
discharge_disposition_id is included (known only at discharge)
Population
Diabetic Patients
130 US hospitals, 1999–2008 (UCI ML Repository)
Scope & Limitations of Claims
  • This is an associative / predictive model, NOT causal. We cannot claim that any feature causes readmission.
  • Results apply to the study population and have not been externally validated on data from other hospitals or time periods.
  • The dataset is historical (pre-2008) — clinical practices, coding systems, and treatment protocols may have changed significantly since then.
  • Prediction at discharge limits the time window for preventive interventions — earlier warnings (e.g., at admission) would be more actionable but would lose access to discharge-related features.

Data Quality Issues Identified & Addressed
  • weight column: 97% missing → dropped
  • encounter_id: identifier only → dropped

  • Raw ICD-9 diagnosis codes: grouped into 9 clinical categories
  • 73+ medical specialties: grouped into 17 meaningful categories
  • Lab results (max_glu_serum, A1Cresult): blank/None values recoded to semantic "Not measured" category

Preprocessing & Statistical Reasoning

10 pts
Data Pipeline — Ordered Transformation Steps
Level 1 Cleaning (Rule-Based)
Exclude death-related discharges, create binary target readmitted_30d, drop identifiers & constant columns, fill approved Unknown fields.
Diagnosis Grouping
Raw ICD-9 codes → 9 clinical categories: Circulatory, Respiratory, Digestive, Diabetes, Injury, Musculoskeletal, Genitourinary, Neoplasms, Other, Missing.
Specialty Grouping
73+ raw medical specialties → 17 clinically meaningful groups (Unknown, General/Internal Medicine, Emergency Medicine, etc.).
Drug Feature Pruning
11 near-constant drug columns removed after statistical verification: Fisher exact test with Benjamini-Hochberg correction — all adjusted p-values = 1.0, confirming no association with readmission.
Numeric Features (8 columns)
Median imputation + StandardScaler. Learned statistics are refit inside each CV fold.
Categorical Features (25 columns)
Constant imputation to "Unknown" + OneHotEncoder(handle_unknown="ignore"). Encoding is refit inside each CV fold.
Final Feature Space
189 encoded features ready for model training.
🔒 Critical Leakage Prevention Measures
  • Patient-level splitting using GroupShuffleSplit by patient_nbr — all encounters for a patient go to the SAME split
  • Preprocessing refit inside each CV fold — imputation, scaling, and encoding parameters are learned only from training data within each fold. No information from validation/test data leaks into training.
  • The held-out test set has NEVER been evaluated — final conclusions await test evaluation

Baseline & Method Selection

15 pts
Baseline: Unweighted Logistic Regression

The simplest parametric classifier and a standard starting point for clinical prediction tasks. Uses L2 regularization (C=1.0), solver=lbfgs, max_iter=2000, random_state=42.

Rationale: Serves as an interpretability reference — if complex models don't substantially outperform logistic regression, the predictive signal may be inherently weak.

Models Compared & Rationale
#ModelKey ConfigurationWhy Selected
1 Class-Weighted LR class_weight="balanced" Addresses the 11% positive rate; tests whether reweighting helps the baseline
2 Random Forest 300 trees, balanced_subsample, sqrt features Captures nonlinear feature interactions; handles mixed feature types
3 Feature Engineering Experiment RF + medication_changes_count + has_specialty Tests whether hand-crafted features add value
4 CatBoost 1000 iter, depth=6, lr=0.05, auto_class_weights=Balanced Gradient boosting with native categorical handling, no one-hot encoding needed
5 LightGBM 1000 estimators, lr=0.05, num_leaves=31, class_weight=balanced Gradient boosting with different regularization strategy
⚠️ Feature Engineering Result: Adding medication_changes_count and has_specialty to Random Forest produced slightly worse results — CV PR-AUC: 0.217 vs 0.219 baseline; Validation PR-AUC: 0.201 vs 0.205 baseline. These features were not adopted.
Key Observation: discharge_disposition_id is included because predictions are made at discharge. If predictions were needed at admission, this feature (ranked #3 in importance) would need to be removed, likely reducing model performance.

Cross-Validation Design
  • 5-fold GroupKFold by patient_nbr within the training split
  • Preprocessing pipeline refit inside every fold
  • Prevents patient-level leakage between folds — no patient's encounters appear in both train and validation within any fold
Metrics Selected & Justification
MetricWhy Selected
PR-AUC (Avg. Precision)Primary metric. Appropriate for imbalanced classification — focuses on minority class performance without being inflated by easy negatives.
ROC-AUCThreshold-independent discrimination measure; allows comparison with published baselines.
F1 ScoreHarmonic mean of precision & recall at a specific threshold; single-number summary for threshold-dependent performance.
Precision & RecallDirectly interpretable for clinical decision-making: "Of those we flag, how many are truly readmitted?" vs "Of those truly readmitted, how many do we catch?"
Balanced AccuracyAdjusts for class imbalance; average of per-class recall.
AccuracyReported but explicitly noted as misleading — 88.6% "accuracy" is just the majority-class rate.
⚠️ Threshold Analysis Caveat: Best-F1 thresholds are selected AND evaluated on the same validation set, so they are optimistic estimates. This is clearly stated throughout and NOT presented as unbiased results.

Key Findings — Presented Honestly
  1. All models achieve similar discrimination: PR-AUC ranges from 0.203–0.213 on validation and 0.217–0.227 on grouped CV. The differences are small and may not be reliable.
  2. CatBoost is marginally best: highest validation PR-AUC (0.213), highest CV PR-AUC (0.227), and highest exploratory F1 (0.282). But the margin over other models is small.
  3. 88.6% accuracy is misleading: the baseline rate is 88.7% — a model that predicts "not readmitted" for everyone achieves similar accuracy.
  4. The precision-recall tradeoff is harsh: at any threshold giving reasonable recall (>30%), precision drops below 25%. The best F1 across all models is only 0.282.
  5. Feature engineering did not help: adding medication_changes_count and has_specialty to Random Forest produced slightly worse results.
  6. Encounter-level features dominate: lab procedures, medications, discharge disposition, and diagnosis group are the most important features — not demographics.
Limitations
  • PR-AUC around 0.20 means the model's discriminative power is limited; ~80% of flagged patients would be false positives at reasonable recall.
  • The dataset is from 1999–2008 and may not reflect modern clinical practices, treatments, or coding systems.
  • Prediction at discharge limits the time window for preventive interventions.
  • discharge_disposition_id (3rd most important feature) encodes discharge destination, which may partly encode the outcome being predicted.
  • No external validation on data from other hospitals or time periods.
  • Multiple encounters per patient create dependency; models treat encounters as independent given the patient-grouped split.
  • The feature engineering experiment tested only two additional features; other transformations may exist but were not explored.
  • Threshold selection on the same validation set inflates reported best-F1 values.
  • Test set performance remains unknown — final conclusions await test evaluation.

Reproducibility & Technical Integrity

How to Reproduce
  1. Download the UCI Diabetes 130-US Hospitals dataset from the UCI Machine Learning Repository.
  2. Run data_cleaning/clean_datav1.py — creates cleaned CSV and an audit log documenting every transformation.
  3. Run preprocessing scripts in order: diagnoses_grouping.py → medical_specality_grouping.py → analyze_drug_features.py → prepare_model_data.py
  4. Run any training script from Training/ — each verifies split alignment and patient disjointness before training.
  5. All random seeds are fixed (42); splits are deterministic and saved to split_assignments.csv.
Data Handling Practices
  • Original data is never modified — each preprocessing step produces a new output file with a numbered suffix.
  • Patient identifiers (patient_nbr) are used only for grouping splits, never as model features.
  • Test set was never evaluated — reserved for final assessment after all modeling decisions are locked.
  • AI tools were used for code development and analysis (disclosed transparently).
